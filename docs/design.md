# 设计：分层导入（越近越完整，越远越压缩）

## 目标

20% 上下文预算内，**尽可能多地保留完整原文+思考**；更早的压缩成线索/点，留在桌面上当触发条件，能顺着 seq 找原文。

## 分层

| 层 | 内容 | 大小 | 用途 |
|---|---|---|---|
| 完整轮 | 最近 N 轮的原始事件（user + assistant，含 reasoning 块与 replayState 签名） | 预算内尽量多（约 23 轮 / 18 万字符） | 一开口就“记得” |
| 线索（thread） | 每轮一个关键词串（引号原话/文件路径/标识符/中文短语）+ 原话开头 | ~150 字符/轮 | 记得“发生过”，能定位 |
| 折叠点（clue） | 从记忆库的压缩点（digests）取最近的几条 | ~400 字符/条 | 最远的历史，关键词索引 |

## 预算

- 完整轮预算 = 总预算 × 0.95（剩 5% 给线索）
- 完整轮从最近往前放；放不下的轮**不删**，降级成线索
- 事件大小只算消息体（不含 stream/usage）

## 曲线

```
保留度
 1.0 ┤████████（最近 ~23 轮：完整）
 0.3 ┤      ▓▓▓▓（更早：线索）
 0.1 ┤          ·  ·  ·（最远：折叠点，留在系统提示里）
 0.0 └──────────────────────────→ 距现在的轮数
```

不是平滑曲线——签名和整条消息绑定，只能整轮保留。所以是「台阶 + 线索层」，而不是指数衰减。

## 完整链路

1. 新会话创建（空 surface）
2. 第一轮 pre-step：`mem.py bootstrap-events --turns 60 --budget-chars 280000 --full-turns 24`
3. 输出 JSON：`[{type:"clue",...}, {type:"thread",...}, {type:"user",data}, {type:"assistant",content,source}, ...]`
4. 插件逐条 append（每条独立 try/catch，失败即停并写日志）
5. 这一轮请求带着这些消息 → 模型开口就记得
6. 之后正常聊：70% 触发压缩、keepRounds=60 保留最近 60 轮

## 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--turns` | 60 | 从多少个真实 user 消息内提取 |
| `--budget-chars` | 280000 | 20% 窗口（字符口径偏保守） |
| `--full-turns` | 24 | 完整轮上限（实际受预算限制） |
| `--clue-count` | 3 | 折叠点条数 |

## 已知局限

- 签名跨会话回放依赖服务端接受（实测同 provider/model 可用）
- 完整轮数受「最近几轮的大小」影响（长分析轮会挤掉更多轮）
- 折叠点目前取记忆库最近 3 条压缩点，可能和完整轮内容有重叠（待优化：只取提取范围之外的）
